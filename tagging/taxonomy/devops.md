# `#devops`

Sous-domaine de `#tech`.

Utiliser pour les contenus principalement consacrés à l'automatisation du déploiement, à l'intégration et au déploiement continus, à la conteneurisation, à l'infrastructure automatisée, à l'exploitation des applications ou aux pratiques reliant développement et opérations.

## Conventions

* Utiliser `#devops` lorsque le contenu porte réellement sur les pratiques, outils ou processus de livraison, déploiement ou exploitation logicielle.
* Ne pas attribuer `#devops` simplement parce qu'un outil couramment utilisé en DevOps est mentionné.
* Ajouter un tag fonctionnel comme `#ci-cd`, `#conteneurisation`, `#iac` ou `#observabilité` lorsqu'il constitue un sujet important du contenu.
* Ajouter le tag d'un outil lorsqu'il constitue lui-même un sujet important, par exemple `#docker`, `#kubernetes`, `#terraform`, `#ansible`.
* Conserver également `#dev` lorsqu'un contenu porte réellement sur le développement logiciel en plus des pratiques DevOps.
* Conserver `#cybersécurité` lorsque la sécurité des infrastructures, des conteneurs ou des chaînes de déploiement constitue un sujet réel du contenu.

## Tags spécifiques courants

* `#ci-cd` : intégration continue, livraison continue et déploiement continu
* `#conteneurisation` : conteneurisation et technologies de conteneurs
* `#iac` : Infrastructure as Code
* `#observabilité` : métriques, logs, traces et supervision des systèmes
* `#docker`
* `#kubernetes`
* `#terraform`
* `#ansible`

## CI/CD

Utiliser `#ci-cd` lorsque les pipelines d'intégration, de test, de livraison ou de déploiement automatisés constituent un sujet important du contenu.

Le tag d'une plateforme ou d'un outil peut être ajouté lorsque celui-ci constitue également un sujet important.

### Exemples

* Introduction à CI/CD : `#tech #devops #ci-cd`
* Pipeline CI/CD avec GitHub Actions : `#tech #devops #ci-cd #github-actions`
* Pipeline GitLab CI : `#tech #devops #ci-cd #gitlab-ci`

## Conteneurs et orchestration

Utiliser `#conteneurisation` lorsque la conteneurisation elle-même constitue un sujet important.

Ajouter le tag de la technologie lorsque cela améliore la classification.

### Exemples

* Introduction aux conteneurs : `#tech #devops #conteneurisation`
* Création d'images Docker : `#tech #devops #conteneurisation #docker`
* Déploiement avec Kubernetes : `#tech #devops #conteneurisation #kubernetes`

Ne pas attribuer automatiquement `#devops` ou `#conteneurisation` lorsqu'un conteneur est seulement utilisé comme moyen pratique pour exécuter un logiciel.

## Infrastructure as Code

Utiliser `#iac` lorsque la définition ou la gestion déclarative de l'infrastructure constitue un sujet important.

### Exemples

* Introduction à l'Infrastructure as Code : `#tech #devops #iac`
* Infrastructure AWS avec Terraform : `#tech #devops #iac #terraform`
* Configuration automatisée avec Ansible : `#tech #devops #ansible`

## Observabilité

Utiliser `#observabilité` lorsque le contenu porte principalement sur la supervision, les métriques, les logs, les traces ou l'analyse du comportement d'un système en production.

### Exemples

* Introduction à l'observabilité : `#tech #devops #observabilité`
* Monitoring avec Prometheus : `#tech #devops #observabilité #prometheus`
* Analyse de logs avec Grafana Loki : `#tech #devops #observabilité #grafana #loki`

## Croisements fréquents

DevOps peut fréquemment croiser d'autres branches sans qu'elles soient pour autant ses sous-domaines.

### Exemples

* Développement et déploiement d'une API : `#tech #dev #devops #api`
* Déploiement d'une application utilisant un LLM : `#tech #devops #ia #llm`
* Sécurisation d'un pipeline CI/CD : `#tech #devops #ci-cd #cybersécurité`
* Sécurité d'un cluster Kubernetes : `#tech #devops #conteneurisation #kubernetes #cybersécurité`

## Cas ne justifiant pas automatiquement `#devops`

* développement d'une application sans sujet lié au déploiement ou à l'exploitation ;
* utilisation locale de Docker uniquement comme environnement de développement ;
* contenu général sur le cloud sans pratique DevOps particulière ;
* administration système sans lien notable avec l'automatisation, la livraison ou l'exploitation logicielle ;
* mention de Kubernetes, Terraform ou d'un autre outil DevOps sans traitement significatif du sujet.
